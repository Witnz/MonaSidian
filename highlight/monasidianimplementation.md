### Implement Monasidian to codeblocks in obsidian
Separate Reading and Editing into separate views. Use highlight.js for reading view and seamlessly switch to Monaco when editing/interacting with a codeblock.

### Customization
Show available languages as checkboxes in groups and Show available themes in a dropdown.
Later versions should have a toggle for automatic language detection after it is implemented


### Implementation methods
For the early implementation, we can ignore autodetection since it can be heavy and lenthy to implement.
Language detection can be based on markdown codeblocks where the language is decided based on the test typed on the same line as the opening backticks.

### Additionals Wishlist
I would like to implement language icons and codeblock titles in a similar fashion to Obsidian Code Styler
Another nice-to-have would be customization of language aliases for the markdown codeblock language names, like go and golang for golang codeblocks or pwsh and powershell for powershell code blocks

## Plan: Pretty Codeblocks via Highlight.js

**TL;DR** — Add a "Codeblocks" rendered feature using Highlight.js for reading mode, Monaco for editing. All 185 hljs language grammars are statically bundled into main.js; only grammars for enabled language groups are registered with the hljs runtime via `hljs.registerLanguage()`. Theme CSS is loaded at runtime from the vendored styles folder via Obsidian's vault adapter. Unregistered or disabled languages fall back silently to Obsidian's native renderer. Default-enabled groups: Common, Config, Web.

---

### Phase 1 — Foundation

**Step 1 — Add highlight.js dependency**
- Add `"highlight.js": "^11.11.1"` to package.json **dependencies** (package ships its own `.d.ts`)
- Import pattern: `import hljs from 'highlight.js/lib/core'`; `import javascript from 'highlight.js/lib/languages/javascript'`
- Vendored es JS files are **not** used as bundle source (confirmed: ES modules with `export default`, but npm package is canonical)
- Vendored `highlight/styles/*.css` **are** used — read at runtime by the vault adapter

**Step 2 — Extend settings.ts**

Add to `MonacoPrettierSettings` interface:
```
enablePrettyCodeblocks: boolean
codeblockTheme: string                          // e.g. "github-dark"
enabledLanguageGroups: Record<string, boolean>  // group name → enabled
languageAliases: Record<string, string>         // e.g. "golang" → "go"
codeblockShowHeader: boolean                    // Phase 2 header bar toggle (default false)
codeblockAllowThemeBackground: boolean          // whether to allow hljs theme to set background color
```

Add to `DEFAULT_SETTINGS`:
- `enablePrettyCodeblocks: false` — opt-in, nothing changes at install
- `codeblockTheme: "github-dark"`
- `enabledLanguageGroups: { Common: true, Config: true, Web: true, ...all other groups false }`
- `languageAliases: {}` — built-in aliases live in `CodeblockLanguages.ts`; user additions stored here
- `codeblockShowHeader: false`
- `codeblockAllowThemeBackground: false` — safe default; prevents hljs dark background clashing with light Obsidian themes

---

### Phase 2 — Language Registry

**Step 3 — Create `CodeblockLanguages.ts`**

Exports:
- `LANGUAGE_GROUPS: Record<string, string[]>` — full 22-group mapping from the spec
- `LANGUAGE_ALIASES: Record<string, string>` — predefined aliases wired in at build time:
  - `golang→go`, `py→python`, `py3→python`, `pwsh→powershell`, `ps1→powershell`, `sh→bash`, `zsh→bash`, `c++→cpp`, `c#→csharp`, `rb→ruby`, `nodejs→javascript`, `node→javascript`, `ts→typescript`, `yml→yaml`
- `LANGUAGE_DEPENDENCIES: Record<string, string[]>` — cross-language grammar deps that must be co-registered:
  - `php-template → [php, xml, css, javascript]`
  - `erb → [ruby, xml]`
  - `django → [xml]`
  - `haml → [ruby]`
  - `dust → [xml]`
  - `handlebars → [xml]`
  - `mojolicious → [xml]`
  - `vbscript-html → [vbscript, xml]`
- `LANGUAGE_REGISTRY: Record<string, Function>` — static map of all ~185 language names to their imported hljs grammar function
- `HLJS_THEMES: string[]` — static list of all theme names (non-min, no extension; image-based themes `brown-paper`/`pojoaque` excluded)
- `getEnabledLanguageSet(settings): Set<string>` — iterates enabled groups, collects all language names into a `Set` (auto-deduplicates cross-group overlaps), then adds transitive deps from `LANGUAGE_DEPENDENCIES`

**Bundle size note**: All 185 grammar functions are imported statically → ~400–500 KB minified added to main.js. Acceptable given Monaco is already several MB.

---

### Phase 3 — CodeblockRenderer

**Step 4 — Create `CodeblockRenderer.ts`**

**`initialize(): Promise<void>`**
- Early return if `!settings.enablePrettyCodeblocks`
- Call `registerEnabledLanguages(settings.enabledLanguageGroups)`
- Call `await applyTheme(settings.codeblockTheme)`

**`registerEnabledLanguages(groups: Record<string, boolean>): void`**
- Build `Set<string>` via `getEnabledLanguageSet()`
- Guard: skip if `!LANGUAGE_REGISTRY[name]` (unknown name)
- Call `hljs.registerLanguage(name, LANGUAGE_REGISTRY[name])` for each name in set

**`applyTheme(themeName: string): async void`**
- Build path: `${plugin.manifest.dir}/highlight/styles/${themeName}.css`
- Read via `plugin.app.vault.adapter.read(cssPath)`
- On read failure → fall back to `default.css`, log a warning
- If `!settings.codeblockAllowThemeBackground`: strip lines matching `/background(?:-color)?:/` from the CSS string before injection (prevents theme background overriding Obsidian's code block styling)
- Find or create `<style id="monasidian-hljs-theme">` in `document.head` → set `.textContent`

**`processCodeblock(el: HTMLElement, ctx: MarkdownPostProcessorContext): void`**

Called once per document section; `el` is a container with rendered HTML — query within it.

1. Master guard: `if (!settings.enablePrettyCodeblocks) return`
2. `el.querySelectorAll('pre > code')` — iterate each `codeEl`
3. **Double-process guard**: `if (codeEl.dataset.monasidianHljs) continue`
4. **Language extraction**: find class `language-xxx` → `xxx`, lowercase
5. **Alias resolution**: check `settings.languageAliases` first (user overrides), then `LANGUAGE_ALIASES` (built-in) → canonical name
6. **No-language guard**: if no `language-*` class found → `continue` (native fallback for unannotated blocks)
7. **Plaintext guard**: if lang is `plain`, `text`, `plaintext`, `nohighlight` → add `.hljs` class only, `continue` (no span injection)
8. **Scope guard**: `if (hljs.getLanguage(resolvedLang) === undefined) continue` — language not registered = not in any enabled group → native fallback; **no error thrown**
9. **Size guard**: `if (codeEl.textContent.length > 500_000) continue` — prevent UI freeze on malformed/huge blocks
10. **Highlight**: `hljs.highlight(code, { language: resolvedLang })` wrapped in `try/catch` — on any hljs error → `continue` (native fallback)
11. **Apply**: `codeEl.innerHTML = result.value` — **safe**: hljs always HTML-escapes user content before wrapping in `<span>` tags
12. **Classes**: add `hljs`, replace `language-{original}` with `language-{resolved}`
13. **Mark processed**: `codeEl.dataset.monasidianHljs = resolvedLang`
14. **Phase 2**: if `settings.codeblockShowHeader`, call `addHeader(preEl, resolvedLang, ctx)`

**`onSettingsChanged(newSettings, oldSettings): async void`**
| What changed | Action |
|---|---|
| Feature toggled off | `cleanup()` → `rerenderAllMarkdownViews()` |
| Feature toggled on | `await initialize()` → `rerenderAllMarkdownViews()` |
| Theme changed | `await applyTheme(newTheme)` |
| Background toggle changed | `await applyTheme(currentTheme)` (re-strips or re-adds background) |
| Group newly enabled | Register net-new languages from that group (call `registerEnabledLanguages` for full set — safe to re-register) |

```typescript
});
```
